## Current official Next Gen fit

### 1. Clear, useful, interesting, original idea

**Evidence status: STRONG_STATIC_SUPPORT**

Second Take has a compact product thesis: rehearse a consequential conversation, save an exact checkpoint, try one response, rewind to the same pre-state, try another response, and compare the consequences.

The differentiator is not merely simulated dialogue. The `Conversation Fork` constrains the comparison so that the pre-fork facts/state are restored and the user's changed choice is the intended variable.

### 2. Meaningful progress toward a working app

**Evidence status: STRONG_RECORDED + STATIC_CODE_SUPPORT + CLEAN_ROOM_PROVIDER_FREE_PASS**

Public source includes:

- a Kotlin/Jetpack Compose Android client;
- a TypeScript/Fastify backend;
- connected repository/ViewModel flow;
- branch capture, rewind, and comparison logic;
- bounded Gemini router/selector clients;
- deterministic fallback and idempotency logic;
- unit/instrumentation test source;
- published video and screenshots.

Historical project audit records report Android build/lint plus 30/30 JVM tests, backend 22/22 tests, and a fresh-clone verification. The 2026-09-18 clean-room follow-up independently passed the current provider-free backend suite and the committed-wrapper Android build/unit/lint/release gates. Credentialed runtime evidence remains separately classified.

### 3. Thoughtful RevenueCat use

**Evidence status: STRONG_STATIC_SUPPORT + RECORDED_RUNTIME_EVIDENCE**

RevenueCat is attached to the value moment rather than placed in front of the core rehearsal:

- conversation is available before purchase;
- the user can experience both paths;
- Full A/B Comparison is the Pro gate;
- the Android client loads the current offering;
- purchases and restores use the RevenueCat SDK;
- access is granted only when `CustomerInfo.entitlements["pro"].isActive == true`;
- the Test Store is explicitly disclosed;
- release builds deliberately receive no Test Store key.

The official Shipaton Next Gen clarification states that Test Store is sufficient for the category.

### 4. Thoughtful technical/product choices and care

**Evidence status: STRONG_STATIC_SUPPORT**

The submission makes several deliberate product/engineering tradeoffs:

- Gemini does not freely author Alex's final response;
- language is mapped into a bounded intent/action system;
- candidate plans are constrained by deterministic policy;
- the selector may choose only from safe candidates;
- a deterministic local fallback selects only from that safe set;
- Intent Lock gives the user explicit control over one high-impact ambiguity;
- backend state owns hidden facts and rewind snapshots;
- idempotency/coalescing limits duplicate turn effects;
- current limitations are disclosed rather than hidden.

## Findings and repairs

### ST-01 — Public submission-status documents contradicted the real submission state

**Severity before repair:** HIGH documentation/evidence risk  
**Status:** FIXED ON HARDENING BRANCH

Multiple public documents still said `NOT_SUBMITTED`, `NOT_YET_SUBMITTED`, `PENDING_JOIN`, `READY_PENDING_PUBLIC_URLS`, or described the Devpost form before final Submit.

That conflicted with the Devpost confirmation email received on 2026-08-29.

**Repair:**

- added `CURRENT_SUBMISSION_STATUS.md` as the canonical current-state record;
- converted old form/readiness files into clearly labeled historical snapshots;
- refreshed the current Shipaton checklist;
- removed stale placeholders from submission metadata.

This preserves the original audit trail without letting an old snapshot masquerade as current truth.

### ST-02 — Android reproduction instructions contained broken paths/references

**Severity before repair:** MEDIUM  
**Status:** FIXED ON HARDENING BRANCH

Problems included:

- backend path documented as `../second-take-backend` although this repository uses `../backend`;
- nonexistent `REVENUECAT_TEST_STORE_SETUP_V08.md` reference;
- instruction to copy from a nonexistent `revenuecat.properties.example`.

**Repair:** Android README now points at the real repository paths and documents the actual untracked `android/local.properties` configuration.

### ST-03 — RevenueCat setup document used an incorrect local path and stale wording

**Severity before repair:** MEDIUM  
**Status:** FIXED ON HARDENING BRANCH

The prior document referenced `second-take-android/local.properties` and described SDK 10.19.1 as "current stable" based on the older audit date.

**Repair:**

- corrected the path to `android/local.properties`;
- states only that this project pins 10.19.1;
- refreshed official documentation references;
- added the official Next Gen Test Store clarification;
- made the debug/Test Store boundary explicit.

### ST-04 — Backend setup guidance was unnecessarily Windows-centric

**Severity before repair:** LOW/MEDIUM  
**Status:** FIXED ON HARDENING BRANCH

The public setup path was primarily PowerShell-oriented and used `npm install` in one backend README while the root reproducibility path relied on the lockfile.

**Repair:**

- documented both PowerShell and POSIX shell commands;
- standardized the reproducible install path around `npm ci`;
- clarified which verification commands are provider-free.

### ST-05 — `configuredProject()` used `cmd.exe` unconditionally

**Severity before repair:** LOW/MEDIUM portability bug  
**Status:** FIXED ON HARDENING BRANCH; CLEAN_ROOM VERIFIED

The backend configuration fallback executed:

`cmd.exe /c gcloud config get-value project`

That is Windows-specific and undermines the otherwise cross-platform setup instructions.

**Repair:** retain the Windows path on Windows and execute `gcloud config get-value project` directly on non-Windows systems.

The follow-up clean-room backend build/test/security/verify sequence passed after this change.

### ST-06 — Google Gen AI manifest used `"latest"`

**Severity:** LOW/MEDIUM reproducibility debt  
**Status:** RESOLVED / CLEAN_ROOM VERIFIED

The hardening follow-up pins `@google/genai` to **2.19.0** in both `backend/package.json` and `backend/package-lock.json`. A networked clean-room then passed `npm ci`, build, tests, security check, and `npm run verify`, eliminating the manifest/lock reproducibility drift.

### ST-07 — Production release build is intentionally not production runnable

**Severity:** EXPECTED MVP LIMITATION, not treated as a Next Gen blocker  
**Status:** OPEN / DISCLOSED

The Android release build deliberately uses a placeholder backend endpoint and disables RevenueCat Test Store. The competition build is a development/demo build rather than a store-ready production release.

Current Next Gen rules do not require store publication, and the project does not claim a production release.

This limitation should remain explicit.

### ST-08 — Independent clean-room reproduction for the current branch

**Severity:** MEDIUM evidence-confidence gap  
**Status:** RESOLVED FOR PROVIDER-FREE GATES

Historical project reports record Android build/lint and JVM tests, backend TypeScript/Vitest checks, fresh-clone verification, secret/PII scanning, and RevenueCat Test Store runtime evidence.

The 2026-09-18 clean-room follow-up independently passed the current backend provider-free verification and the committed-wrapper Android build/unit/lint/release gates. External-service tests remain separately classified because they require credentials/dashboard/runtime access.

### ST-09 — Full human accessibility validation is incomplete

**Severity:** LOW for current eligibility; product-quality limitation  
**Status:** OPEN / DISCLOSED

The repository does not claim a completed human TalkBack audit. Keep this as roadmap/limitation rather than silently upgrading the accessibility claim.

## Security/privacy static review

The current public design keeps Google Cloud credentials outside the Android APK and repository, uses ADC in the local backend, ignores `.env` and `local.properties`, and treats the RevenueCat Test Store key as a debug-only public client key.

No administrative RevenueCat REST secret is part of the documented runtime.

The public-session boundary is designed to expose visible/revealed state rather than raw backend-only policy internals. The existing test source includes a check that unrevealed fact identifiers are absent from the initial public response.

A full secret/history scan was recorded before submission. The clean-room follow-up also reported security hygiene PASS and backend security check PASS after the hardening edits. The present edits intentionally introduce no credential, academic email address, enrollment identifier, or local absolute path.
